## Capa de datos del front original conectada a la API Rust (`/api`)

**Contexto:** el frontend original (App/React + Glory) quedo materializado como SPA sobre Rust; los hooks legacy seguian llamando a `/wp-json/glory/v1/*`. Se conecto cada dominio al backend Rust existente y se degradaron los dominios sin backend.

### Backend (Rust)

- `PUT /api/habits/{legacy_id}`: upsert de habitos (`UpsertHabitRequest`) en `src/models/productivity.rs`, `src/repositories/productivity.rs`, `src/services/productivity.rs`, `src/handlers/productivity.rs` (corregido: `upsert_habit` quedo fuera del `impl` en un primer edit y se movio dentro).
- `PUT /api/dashboard/settings`: scratchpad de notas + configuracion de usuario (`UpdateDashboardSettingsRequest`) en `src/models/dashboard.rs`, `src/repositories/dashboard.rs`, `src/services/dashboard.rs`, `src/handlers/dashboard.rs`, registrado en `src/handlers/mod.rs` (handler + componente OpenAPI).

### Frontend (React)

- **Nuevo cliente compartido** `src/app/utils/apiClient.ts`: `apiFetch` con sesion por cookie + `X-CSRF-Token` en mutaciones, errores `{error, message}` del backend. Bug encontrado y corregido: el body se doble-serializaba (los callers que ya pasaban `JSON.stringify` producian 422) — ahora no se re-serializa un string.
- **Conectados a `/api`**: `useNotificaciones` (con mapeo a `Notificacion`, ids UUID), `useActividad` + `actividadService` (contrato Rust compatible), `useCompartidos` (ids de usuario UUID), `useEquipos` (mapeo de estados pending/accepted/rejected/pending_registration, return aplanado conservado), `notasService`/`carpetasNotasService`, `habitosService` (historial), `useModalPerfil` (`PUT /api/profile`), `useDashboardApi` (persistencia de habitos + settings).
- **Degradados sin romper UI** (sin llamadas a `/wp-json`): mensajes (+no-leidos, +utils/mensajes), almacenamiento, backups, administracion, feedback (admin y modal), cifrado E2E, MCP (config local), grupos FB (hook + service), chatbot-config, Google Login, recuperar contrasena, notificacion de prueba, limpiar actividad. `obtenerApiUrlWP` devuelve `/api` para que los servicios IA/agente fallen con 404 JSON de Rust.
- **Shim de sesion**: `window.gloryDashboard` ahora es solo el contexto de sesion Rust (`isLoggedIn`, `currentUser.id` UUID, `apiUrl`→`/api`).
- **Slice viejo retirado**: `frontend/src/features/*` y `frontend/src/App.tsx` eliminados (nada los importaba).

### Evidencia

- `tsc --noEmit` OK (780+ archivos), `vite build` OK (2608 modulos), `cargo check` OK, `cargo test` 10/10 OK.
- En vivo contra el backend: `PUT /api/tasks/{1,2,3}` 200, `PUT /api/habits/{id}` 200, `PUT /api/habits/{id}/history` 200 (marcar/desmarcar dias), `PUT /api/dashboard/settings` 204, `GET /api/teams/pending-count` 200, `GET /api/notifications/unread-count` 200.
- En BD: `dashboard_habits` con "Meditación matutina" (frecuencia diario), `dashboard_settings` con notas/config persistidos.

### Decisiones / gotchas

- El contrato Rust devuelve JSON plano (sin envelope `{success,data}`) y usa UUIDs; cada hook mapea al tipo del front. Los ids UUID se pasan como string en runtime dentro de tipos `number` (solo se usan como claves/igualdad, sin aritmetica).
- `habitosIniciales` de bienvenida solo se suben en la primera inicializacion del usuario (semantica original del sync manager); un usuario ya inicializado que no tenia habitos en el servidor los vera vacios hasta crear uno (la creacion persiste).
- `frecuencia` del front es objeto `{tipo}`; Rust espera string → mapeo en `habitoARequest`.
- Backend y frontend conviven en este repo; los commits del bloque se hicieron sobre la rama `main` del repo local `task`.

## Paridad completa: dominios recuperados contra Rust (mensajes, suscripción, almacenamiento, backups, WebSocket, admin, cifrado E2E, MCP)

**Contexto:** el objetivo del producto es que todo lo que funcionaba en WordPress funcione aqui. Se implementó backend real para los dominios que estaban degradados y se conectó el front, dejando solo los que requieren credenciales externas (IA/WhatsApp/Google/Facebook/Stripe reales/MCP server).

### Backend (Rust)

- **Migración** `migrations/20260826000000_parity_domains.{up,down}.sql`: tablas `subscriptions`, `attachments`, `backups`, `feedback`, `e2e_keys`, `api_tokens` y columna `users.es_admin`.
- **Nuevos módulos** (modelos + repositorios + servicios + handlers + rutas en `src/handlers/mod.rs`):
  - `subscription`: `GET /api/subscription`, `POST /subscription/trial` (14 días), `POST /subscription/checkout` (degradado explícito sin llaves Stripe). Límites por plan.
  - `storage`: `GET /api/storage`, `POST /storage/verify`, `GET|POST /api/storage/files` (multipart, guarda en `uploads/{user}/`, 5 MB máx), `GET|DELETE /api/storage/files/:id` (descarga autenticada por cookie).
  - `backup`: `GET|POST /api/backups` (snapshot del dashboard), `POST /backups/:id/restore` (reescribe settings y hace upsert de tareas/proyectos/hábitos), `DELETE /backups/:id`.
  - `feedback`: `POST /api/feedback` (límite diario 3), `GET /feedback/state`, `GET /feedback/mine`, admin `GET /admin/feedback`, `GET /admin/feedback/stats`, `POST /admin/feedback/:id/read` (guard `es_admin`).
  - `security`: `GET|PUT /api/security/e2e` (clave generada en cliente, blob en BD), `PUT /security/password` (argon2 + invalida `auth_sessions`), `GET|POST /api/security/mcp/token`, `DELETE /security/mcp/token/:id` (hash argon2).
  - `admin`: `GET /api/admin/users` (JOIN users+subscriptions+e2e_keys+contadores, filtros/paginación), `GET /admin/users/:id`, `GET /admin/stats`, `POST /admin/users/:id/premium|cancel-premium|trial`.
  - `realtime`: `GET /api/realtime/ws` — WebSocket autenticado por cookie, hub en memoria con broadcast por `user_id` (`RealtimeHub` global); `TimelineService::send` publica eventos `{type:"timeline"}` a los participantes.
- **Modelo usuario**: `es_admin` añadido a `User`/`UserResponse` y a todos los SELECT del repositorio.
- Cargo.toml: `futures-util` (sink), features `multipart` y `ws` de axum; límite de body global a 6 MB para adjuntos.

### Frontend (React)

- **Mensajes/chat**: `useMensajes`, `useMensajesNoLeidos` y `utils/mensajes` conectados a `/api/timeline` (list/send/events/unread/read); `MensajeTimeline.id`/`usuarioId` pasan a string (UUID).
- **Suscripción**: `useSuscripcion` → `GET /api/subscription` + `POST /subscription/trial` (carga al montar).
- **Almacenamiento**: `useAlmacenamiento` → `GET /api/storage` + `POST /storage/verify`.
- **Backups**: `useBackups` → list/create/restore/delete.
- **Cifrado E2E**: `useCifrado` → `GET|PUT /api/security/e2e` (clave AES-GCM 256 bits generada en cliente).
- **Admin**: `useAdministracion` mapea endpoints al contrato Rust (`/admin/users`, `/admin/stats`, `/admin/users/:id/premium|cancel-premium|trial`); `UsuarioAdmin.id` a string (tipos + componentes + `usePanelAdministracion`).
- **Feedback**: `useModalFeedback` → state + create; `useListaFeedbackAdmin` → list + marcar leído (id string).
- **MCP**: `useModalConfiguracionMCP` → get/generate/revoke token (`/api/security/mcp/token`), token plano mostrado una sola vez.
- **Perfil**: cambio de contraseña en `handleSubmit` (`PUT /api/security/password`, invalida sesiones → re-login).
- **Tiempo real**: `useWebSocket` apunta a `ws(s)://host/api/realtime/ws` (mismo origen, ping/pong con texto plano), nuevo `utils/eventBus.ts` y `useMensajes` recarga al recibir evento `timeline` del elemento activo.

### Bugs encontrados y corregidos durante la verificación en vivo

- `SUM(tamano)` de PostgreSQL devuelve NUMERIC → cast `::BIGINT` en `sum_size`.
- El id del adjunto en disco no coincidía con el id auto-generado por la BD → insert con `id` explícito.
- `DELETE FROM sessions` → la tabla real es `auth_sessions`.
- **Rutas axum 0.7**: las rutas nuevas usaban sintaxis `{id}`; el proyecto usa `:id` (axum 0.7) → convertidas en backup/storage/security/admin/feedback (el 404 vacío delataba que no matcheaban).

- `tsc --noEmit` OK, `vite build` OK, `cargo check` 0 warnings, `cargo test` 10/10 OK.
- En vivo (curl + Node): suscripción → trial 13 días; storage info + upload multipart + descarga 200 (id consistente disco/BD); backups create/list/restore; feedback state/create + admin list/read 204; admin users/stats/detail; e2e PUT; mcp generate; password change 200 (sesión invalidada); **WebSocket**: handshake `connected` + ping/pong + broadcast de `timeline` al enviar un mensaje.

### Decisiones / gotchas

- El cambio de contraseña invalida todas las sesiones (diseño: re-login obligatorio tras cambiar credenciales).
