## Refactor visual monocromo (318A-1): blanco y negro puro, sin radios, sin sombras

**Plan:** `Agente/planes/plan-refactor-monocromo-2026-08-31.md`.
**Estado:** completo, verificado y gate PASS. Sin pendientes.

### Qué se hizo

1. **`variables.css` reescrito a monocromo** (2 temas): `:root` = tema oscuro base (`original`,
   fondos `#000000`/`#0a0a0a`, texto `#ffffff`→`#4d4d4d`, bordes `#2a2a2a`/`#1c1c1c`) y
   `[data-theme='claro']` = tema blanco. **Todos los `--dashboard-radio*` = `0` y todos los
   `--dashboard-sombra*` = `none`.** No existe `[data-theme='oscuro']`.
2. **Eliminado el tema `oscuro`** de `useTema.ts` (`TipoTema = 'original' | 'claro'`) y de las
   referencias TSX: `SeccionConfigLayout.tsx`, `SeccionConfigTemas.tsx`,
   `ModalConfiguracionLayout.tsx`, `ModalTemas.tsx`, `DashboardIsland.tsx`,
   `GaleriaVisualIsland.tsx`. `useDashboardApi.ts` conserva `'oscuro'` a propósito (contrato API
   de datos persistidos, no es selector de UI).
3. **`monocromo.css` (nuevo)**: anulación global `[data-theme] * { border-radius: 0 !important;
   box-shadow: none !important; }` + foco accesible con `outline` (nunca box-shadow). Importado
   **al final** de `styles/dashboard/index.css` — este posicionamiento fue crítico: antes el
   `@import` estaba tras `@font-face` (CSS inválido, se descartaba).
4. **Limpieza de hardcoded en 13 archivos CSS** (fallbacks de color/radio/sombra → tokens
   `--dashboard-*` o `0`/`none`): `panelAgente.css`, `panelIA.css`, `ConfigExp.css`,
   `modalEditorArbol.css`, `PanelExp.css`, `sidebarMenu.css`, `badgeInfo.css`,
   `dashboardSidebarGrid.css`, `layoutManager.css`, `recordatorios.css`,
   `constructorPaginas.css`, `editorPixelArt.css`, `glory-core/index.css`. Además
   `glory-core/index.css` radios de `.prose` → `0`.
5. **Guard automático VarSense**: `hardcodedDetection` activo con `allowedValues`
   (`0/0px/auto/inherit/initial/unset/transparent/currentColor/none`) — cualquier
   radio/sombra/color nuevo fuera de la lista (incluidos fallbacks de `var()`) se reporta solo.
   `bannedProperties.properties` se deja **vacío a propósito**: su semántica marca CUALQUIER
   declaración de la propiedad (sin filtrar valor), así que incluir `border-radius`/`box-shadow`
   generaría falsos positivos sobre `border-radius: 0`/`box-shadow: none`, ahora la norma.
