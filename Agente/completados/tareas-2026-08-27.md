## Plugin EXP — panel real registrado (corrección 3, 27-08-2026)

**Petición del usuario:** el panel de Game (plugin EXP), cuando el plugin está activo, se
montaba como barra fija directa en `DashboardIsland` — "parece un panel pero no lo es; en
sidebar no queda bien ahí arriba fijo". Pedía que fuera un **panel real individual** en el
modo sidebar como el resto de paneles, y en el otro modo en la misma posición pero como
panel real.

### Qué se hizo

El panel `exp` deja de ser un montaje directo y pasa al **registro OCP de paneles**:

- `frontend/src/app/plugins/exp/index.ts`: `registrarPanel({id: 'exp', titulo: 'Game',
  tituloMovil: 'Game', icono: Heart, visiblePorDefecto: false, alturaDefecto: 'auto',
  posicionDefecto: {1: {columna: 1, posicion: 0}, 2: {...}, 3: {...}}, componente:
  PanelExp, enNavegacionMovil: false, idPaginaMovil: 'exp', manejaAlturaPropia: false})`.
  `panelesIds: []` → `['exp']` (el toggle del plugin muestra/oculta el panel).
  `enNavegacionMovil: false` sigue la convención de todos los paneles de plugins (la
  navegación móvil real usa `obtenerTodosPanelesNavegables`, que no filtra por ese flag).
- `frontend/src/app/hooks/dashboard/generadoresPropsPanel.ts`: nuevo generador `exp` →
  `onAbrirConfig` abre `abrirModalPluginsConConfig('exp')`; añadido a `GENERADORES_PROPS`.
- `frontend/src/app/plugins/exp/PanelExp.tsx`: interfaz `PanelExpProps extends
  PanelBaseProps` (`renderHandleArrastre`, `handleMinimizar`, `onAbrirConfig?`); raíz
  `div.panelExp` (antes `panelDashboard panelExpFijo`); encabezado con
  `renderHandleArrastre('Game')` + acciones Editar árbol/Configurar + `handleMinimizar`;
  se eliminan GripVertical/Minus/minimizado local (el minimizar lo gestiona el sistema de
  paneles). El cuerpo se renderiza siempre (sin wrapper `!minimizado`).
- `frontend/src/app/plugins/exp/PanelExp.css`: `.panelExpFijo` → `.panelExp` (sin
  `margin-bottom` extra); `.seccionTitulo` sin `text-transform`; se elimina el bloque de
  posición `static` del sidebar.
- `frontend/src/app/plugins/exp/store.ts` / `types.ts` / `useExpPlugin.ts`: se eliminan
  `minimizado` y `alternarMinimizado` (estado que ya no aplica a un panel gestionado).
- `frontend/src/app/islands/DashboardIsland.tsx`: se eliminan los dos montajes directos
  `<PanelExp .../>` (grid + sidebar); el panel se renderiza vía registro. Import pasa a
  `useExpPlugin`.
- `frontend/src/app/config/inicializarPlugins.ts`: comentario actualizado.

### Bug CSS encontrado y corregido en la verificación

En el modo sidebar, `dashboardPanelView.css` tiene un bloque `[300A-5]` que pone
`background-color: transparent !important; border: none; box-shadow: none` sobre
`[class*="panel"]` (para paneles genéricos). Mis excepciones `.panelExpBarra` usaban
`var(--dashboard-fondo)` y `var(--dashboard-aviso)` **sin fallback**, pero esos tokens NO
existen en `variables.css` (solo `--dashboard-fondoSecundario`); una `var()` sin fallback
+ `!important` invalida la declaración → la barra quedaba transparente.
**Fix:** mismas excepciones con los fallbacks que ya usa `PanelExp.css`
(`var(--dashboard-fondo, rgba(255,255,255,0.07))`, `--dashboard-aviso, #e0a83c`,
`--dashboard-exito, #4caf7d`, `--dashboard-error, #e0544c`, `--dashboard-acento, #7c9cff`,
`--dashboard-textoActivo, #e8e8ea`). Verificado en vivo: track
`rgba(255,255,255,0.07)`, relleno Vida `rgb(239,68,68)` (baja), EXP
`rgb(96,165,250)` (acento), árbol `0.8px solid rgb(245,245,245)` + relleno `currentColor`.

### Gotchas / decisiones

- **Tokens CSS ausentes**: `--dashboard-fondo` y `--dashboard-aviso` NO existen en
  `variables.css`; toda excepción/override sobre paneles debe incluir el fallback (igual
  que el CSS origen), si no la declaración con `!important` se descarta en silencio.
- El minimizar y el arrastre los gestiona el sistema de paneles (no el plugin); el estado
  local `minimizado` del store era redundante y se eliminó.
- `manejaAlturaPropia: false` para que el grid gestione la altura del panel.
