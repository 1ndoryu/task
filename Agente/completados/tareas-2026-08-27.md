En el modo sidebar, `dashboardPanelView.css` tiene un bloque `[300A-5]` que pone
`background-color: transparent !important; border: none; box-shadow: none` sobre
`[class*="panel"]` (para paneles genéricos). Mis excepciones `.panelExpBarra` usaban
`var(--dashboard-fondo)` y `var(--dashboard-aviso)` **sin fallback**, pero esos tokens NO

`rgba(255,255,255,0.07)`, relleno Vida `rgb(239,68,68)` (baja), EXP
`rgb(96,165,250)` (acento), árbol `0.8px solid rgb(245,245,245)` + relleno `currentColor`.

## Scroll interno en modo sidebar (27-08-2026)

**Petición del usuario:** en modo sidebar, cuando las tareas superan la altura, el scroll
aparece "por fuera" (en el body/página o en el contenedor exterior) en vez de dentro del
contenido del panel.

### Causa raíz (doble)

1. `.dashboardContenedor--sidebar` usaba `min-height: 100dvh` (no `height` fija), así que
   el contenedor **crecía con el contenido** en vez de acotarse al viewport → el exceso
   empujaba el scroll al body/página.
2. `.dashboardPanelContent` tenía `overflow: hidden` (recorta, nunca hace scroll) y
   `.listaTareasPendientes` `overflow: visible` → **ningún elemento dentro del panel
   hacía scroll**; el scroll "visible" era el de `.dashboardSidebarContenido`
   (`overflow-y: auto`), que queda por fuera del contenido del panel.

### Qué se hizo (3 archivos CSS)

```css
/* base.css */
.dashboardContenedor--sidebar {
    padding: 0;
    height: 100vh;   /* Fallback */
    height: 100dvh;  /* Acota el sidebar al viewport */
    overflow: hidden;
}

/* sidebarMenu.css */
.dashboardSidebarContenido {
    /* overflow-y: auto → overflow: hidden */
    overflow: hidden;  /* Ya no es el contenedor exterior de scroll */
}

/* dashboardPanelView.css */
.dashboardPanelView .dashboardPanel {
    flex: 1;
    min-height: 0;  /* El DashboardPanel interno llena la altura restante */
}
.dashboardPanelView .dashboardPanelContent {
    overflow-y: auto;   /* Scroll interno del contenido del panel */
    overflow-x: hidden;
    min-height: 0;
    padding-bottom: var(--dashboard-espacioLg); /* Última tarea no cortada */
}
```

El patrón replica `.panelAlturaFija .panelDashboard .dashboardPanelContent` de
`resizePanel.css` (modo grid). Aplica igual al multi-panel porque las celdas
(`sidebarGridCelda`) reutilizan `DashboardPanelView`.

### Evidencia

- `npx tsc --noEmit -p tsconfig.json` → EXIT 0.
- Verificación Playwright a viewport 700×700 (panel Tareas con muchas tareas):
  - `docScrollHeight 700 == innerHeight 700` → **sin scroll de página**.
  - `.dashboardPanelContent`: `clientHeight 634` / `scrollHeight 988` / `overflow-y auto`
    → es el **único** elemento con scroll, la barra aparece dentro del panel.
  - `scrollTop = 200` aplicado y leído → scroll **funcional**.
  - `.dashboardSidebarContenido`: `overflow: hidden`, sin desborde (`680 == 680`).
  - Panel Actividad (no usa `dashboardPanelContent`): sin scroll de página y sin desborde
    (su contenido cabe) — sin regresión.

### Gotchas / decisiones

- Para confinar el scroll en una cadena flex hacen falta **dos cosas**: (a) altura acotada
  en la raíz (`height`, no `min-height`) y (b) el elemento destinado a scroll con
  `overflow-y: auto` + `min-height: 0` en toda la cadena de ancestros.
- No se tocó `.dashboardPanelContent` global (compartido con grid): el fix está acotado a
  `.dashboardPanelView` (solo sidebar), así el modo grid no cambia.
- `get_errors` reporta hardcodeos/box-shadow **preexistentes** en estos CSS (no
  introducidos por este cambio).
